発展編

カードZIPを、自分で作る。

ファイルの役割を理解して、画像とカード情報をまとめ、取り込みを確かめます。

更新：2026年9月27日 · 画面例：iOS版 1.0.0の開発ビルド
端末・OS・ゲーム設定により、表示や配置が異なる場合があります。

画面例にはデモカードを使っています。実際に使うのは、ご自身のカード画像や受け取ったカードZIPです。ゲーム名・カード名・枚数を読み替えて進めてください。デモデータの入手は不要です。

1. ZIPの構造を知る

カードZIPは、ゲーム名と属性定義・カード情報・画像をまとめたファイルです。人のZIPを使うだけなら入門編の取り込み手順へ進めます。

my-cards/
├── game.json
├── cards/
│   └── cards.json
└── images/
    ├── DMO-R05.jpg
    ├── DMO-R12.jpg
    └── DMO-R12_p1.jpg
以下のカード名・画像名はデモの説明例です。ご自身の情報・画像に置き換えてください。盤面・クイック操作・組み上がったデッキはこのZIPに含まれません。

2. game.jsonを作る

UTF-8のテキストで保存します。拡張子が .json.txt にならないよう確認してください。format と version は固定、名前と属性は自分のゲームに合わせます。

{
  "format": "tcgt-cards",
  "version": 1,
  "game": {
    "name": "デモカードゲーム",
    "fields": [
      { "key": "color", "label": "色", "type": "select", "options": ["赤", "青", "緑", "黄"] },
      { "key": "kind", "label": "種類", "type": "select", "options": ["ユニット", "魔法", "フィールド"] },
      { "key": "cost", "label": "コスト", "type": "number" },
      { "key": "power", "label": "パワー", "type": "number" }
    ]
  }
}

key は属性の識別子、label は表示名です。select の options には選択肢を入れます。型番とカード名は fields へ追加しません。

3. カードのJSONを作る

cards/cards.json にカードの配列を保存します。code と name は必須です。images の先頭が代表の絵、2枚目以降はパラレルです。

[
  {
    "code": "DMO-R05",
    "name": "炉尾の仔",
    "attributes": { "color": "赤", "kind": "ユニット", "cost": 1, "power": 1000 },
    "images": ["images/DMO-R05.jpg"]
  },
  {
    "code": "DMO-R12",
    "name": "熔冠の獣",
    "attributes": { "color": "赤", "kind": "ユニット", "cost": 6, "power": 9000 },
    "images": ["images/DMO-R12.jpg", "images/DMO-R12_p1.jpg"]
  }
]
属性の型値の例
text"説明文"
number1000
select"赤"
multiselect["赤", "青"]
booleantrue
デモの色は select なので文字列です。複数選択として設計した場合は配列にします。デッキに3枚入れるためにカードを3行書く必要はありません。採用枚数はデッキ作成で指定します。

4. 画像のパスを合わせる

  • 自分の画像を images/ へ保存します。画像URLを書く方式ではありません。
  • ファイル名は半角英数字と - _ . を使うと扱いやすくなります。
  • パスはZIP内からの相対パス。先頭の / や ./、上の階層へ戻る .. は使いません。
  • 大文字小文字・拡張子を一致させます。
  • 用意しないパラレル画像のパスは削除します。

同じ型番は同じカードとして扱われます。絵違いは1件の images にまとめると管理しやすくなります。

5. ZIPに圧縮する

game.json・cards/・images/ を同じフォルダに置き、そのフォルダをZIP形式に圧縮します。外側のフォルダ1階層は取り除いて読めますが、何重にも包まないでください。

パスワード付きZIP・ZIP64は非対応です。4GB未満、ファイル数65,535未満に収め、まず少数のカードで確認します。

Pythonで作る場合

Python 3が使える環境で、my-cards の隣に make_zip.py として保存し、python3 make_zip.pyを実行します。既存ZIPは上書きしません。

from pathlib import Path
import json
import zipfile

source = Path(__file__).resolve().parent / "my-cards"
output = source.parent / "my-cards.zip"
assert (source / "game.json").is_file(), "game.jsonがありません"
assert list((source / "cards").glob("*.json")), "カードJSONがありません"
files = sorted(p for p in source.rglob("*") if p.is_file())
assert len(files) < 65535, "ファイル数が上限を超えています"
for path in [source / "game.json", *sorted((source / "cards").glob("*.json"))]:
    json.loads(path.read_text(encoding="utf-8"))
with zipfile.ZipFile(output, "x", compression=zipfile.ZIP_STORED,
                     allowZip64=False) as archive:
    for path in files:
        archive.write(path, path.relative_to(source).as_posix())
print(output)

6. アプリへ取り込んで確かめる

  1. ZIPを端末または開けるクラウドへ保存します。
  2. カード一覧の「＋ 追加」→「ZIP を選ぶ」で開きます。
  3. 件数・画像数・警告を確認します。この例ではカード2種類・画像3枚です。
  4. 下書きを確認して保存し、名前・型番・属性・パラレルを確認します。

最初は新しい確認用ゲームへ入れると、既存カードへの追加を避けて確認できます。新しいゲームとして取り込んだ場合、遊ぶための盤面とデッキ設定は別に用意します。

7. 枚数を増やす・AIを使う

cards/set1.json、cards/set2.json のように複数ファイルへ分けられます。各ファイルをカードの配列にします。

アプリの「AI 用の仕様をコピー」をAIへ渡し、カード情報と実在する画像ファイル名の一覧を添えます。不足情報は推測させず一覧にし、大量の場合は生成用スクリプトと実行手順を依頼します。少数で取り込みを確認してから増やしてください。

登録済みカードからなら、カード一覧の「書き出す」でも同じ形式のZIPを作れます。型番がないカードは採番の確認が入ります。

読めないときに確認するところ

症状確認すること
game.jsonがない階層、ファイル名、拡張子
JSONを読めないカンマ、引用符、括弧、UTF-8
画像が見つからない実ファイルと相対パス、大文字小文字
属性が空になるkey、値の型、optionsとの一致
件数が少ない同じ型番にまとめられていないか
再取り込みで増えない同じ型番・同じ絵はスキップされます
